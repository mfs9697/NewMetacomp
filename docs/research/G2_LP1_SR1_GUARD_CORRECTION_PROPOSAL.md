# G2-LP1-SR1 — proposed corrections to the guarded LP1 code (proposal only)

[Issue #56](https://github.com/mfs9697/NewMetacomp/issues/56), SR1-C. **No file in PR #55 is changed by SR1.** Policies, source pins and safeguards remain exactly as at `70bf6f4`.

Each item below would need a new versioned policy or source set, review, and a fresh prephysical qualification before use.

| ID | Observation at `70bf6f4` | Effect | Proposed correction |
|---|---|---|---|
| P1 | In `check_g2_lp1_contract.m`, `reject()` counts *any* thrown error as a successful negative. | A negative test can pass for an unrelated reason, such as a path error or a preflight failure. | Assert the expected `ME.identifier` for each negative, e.g. `G2LP1:HOLD_UNAUTHORIZED_STATE`, `G2LP1:HOLD_SOURCE`, `G2LP1:HOLD_RECORD_INTEGRITY`. |
| P2 | Because `G2_LP1_SCIENTIFIC_GO_v1.json` never exists, `scientific_go_missing_or_wrong_token` always fails at `isfile`. | The *present but mismatched* GO branches (wrong policy, source, LP0, token or contract-evidence hash) are never executed. | Let `g2_lp1_scientific_gate` accept a test-only GO path outside `matlab/g2` (e.g. a temporary folder). Add fixtures for each mismatch, and one complete *synthetic* GO that must still fail on the contract-evidence hash. Never write a GO under `matlab/g2`. |
| P3 | `g2_lp0_clearance` sets `status = reasons{1}` with the fixed order EXTERNAL > SELF_INTERSECTION > INTERFACE > Q_PHASE > TIP_GUIDE. The miter criterion (turn > 36.87°) is reported as `HOLD_CRACK_SELF_INTERSECTION`. | All reasons are retained, but the primary label can misstate the physical cause. In the 23 clearance tests, ring-tunnel probes report `SELF_INTERSECTION` first because of the probes' sharp kink. | Introduce a separate `HOLD_KINK_ANGLE` code and a documented priority based on physical meaning. Keep the full `reasons` list. |
| P4 | `HOLD_TIP_GUIDE` (15 mm) always precedes `HOLD_INTERFACE_APPROACH` (1.52 mm) on a smooth approach. | An LP2 run toward a ring will report a guide HOLD about 15 mm before the interface. That is correct, but easily misread as "interface approach". | State this explicitly in any LP2 policy and in the figure captions. |
| P5 | In `g2_lp1_run`, `resource()` (the 5-GiB check) is called after `mkdir(sd)`. | A transient memory dip creates a state folder plus `HOLD.mat`, which permanently blocks the chain until a documented investigation. | Call `resource()` before `mkdir(sd)`, so a memory HOLD leaves no partial state. Keep the 5-GiB threshold and the no-retry rule. |
| P6 | The prephysical batch measures RAM in `g2_lp0_preflight` and again in every `g2_lp1_context` call. In the PR #55 run, the first check passed at 5.380 GiB and a later one failed at 4.958 GiB. | A batch near the threshold fails midway, as happened. | Do not change the threshold. Add an operational prerequisite (e.g. start only when the OS reports ≥ 7 GiB free) and record every RAM observation in the result JSON. |
| P7 | With `core.autocrlf=true` (the default on the investigator's machine), checkouts convert pinned JSON to CRLF. The working-tree SHAs then differ from the pins (policy v2 `50b2ee2a…` on disk vs. `074d7edc…` in Git). | Preflight fails with `HOLD_POLICY_DRIFT` on such a checkout. Reproduction depends on per-clone settings. | Add `.gitattributes` entries (`matlab/g2/*.json -text` or `eol=lf`) in a reviewed change, or keep documenting `core.autocrlf=false` as mandatory. |
| P8 | `Invoke-G2LP1-PrephysicalBatch.ps1` requires the branch name `research/g2-lp0-lp1-implementation-20261122`. | Re-execution from a stacked review branch (such as SR1's) or a detached clone needs a local branch of that name. | Accept an explicit expected commit SHA instead of, or in addition to, the branch name. |
| P9 | The primary uncertainty floor of 1e-5 in F_G (inherited from M3) is smaller than the R1 cross-family drift of these exact architectures (2.1–3.1e-5). The conservative rule sums a common-mode COD bias (−0.877 … −0.879 % in K_I in all 20 states). | The primary rule understates mesh-family sensitivity by about ×2–3. The conservative rule is not informative for paired comparisons. Neither is a certified bound. | Prospectively preregister (i) a paired-estimator rule, U = max over estimators of \|F_G^est − F_G^EDI\| with the same estimator on both sides; (ii) a floor of at least the R1 drift; (iii) a refinement-based discretization estimate at selected states. Never reclassify LP1 retroactively. |
