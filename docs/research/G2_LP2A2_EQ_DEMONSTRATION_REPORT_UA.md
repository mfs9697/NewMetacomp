# G2-LP2-A2. Демонстрація еквівалентності КІН (кампанія G2-LP2A2-EQ-001)

**Статус: `HOLD_LP2A2_EQ_ACTIVATION_BINDING_WINDOWS_CARET`.** Жодного розв’язку не виконано. Еквівалентність **не встановлено і не спростовано**: даних для порівняння C1–C11 немає.

Це не відмова методу чи сітки. Правильно створений коміт активації GO не пройшов передзапускову суху перевірку: валідатор `g2_lp2a2_eq_go_validate` на цьому Windows-комп’ютері хибно відхиляє його. Згідно з протоколом (джерела `matlab/g2/**` не змінюються, закріплення не перезакріплюються, обхідні шляхи не застосовуються) кампанію зупинено до першого виклику обгортки.

## 1. Хронологія

1. **Ресурси (перша спроба, до GO).** Протягом 543 с вільна фізична пам’ять не перевищила 6,108 ГіБ (потрібно ≈ 8,2 ГіБ перед запуском). Паралельно інша сесія тримала власний процес MATLAB (`g2_prelim_figures_b`). Запобіжники 5 і 7 ГіБ не змінювалися, чужі процеси не зупинялися, GO не створювався, комітів немає.
2. **Продовження за вказівкою дослідника.** Голови, чистота, контрольні суми повторно перевірено: зовнішня перевірка хешів — усі 13 перевірок істинні (токен збігається з шаблоном, 20 архівних хешів, докази 64/64); захищені записи — 541 + 158 = 699 без змін; `D:` — змінний носій, вільно 3,2 ГБ.
3. **Передперевірка в MATLAB R2023a (GO відсутній).**
   - Спроба 1: після завантаження контексту доступно 7,010 ГіБ — нижче додаткового запасу 7,3 ГіБ (запобіжник 7 ГіБ пройдено). Сесію закрито, GO не створювався; журнал збережено (`lp2a2_eq_activation_checks_wait1.log`).
   - Спроба 2 (вільно перед запуском 8,173 ГіБ): доступно 7,468 ГіБ ≥ 7,3; рівно один рушій MATLAB; PDE Toolbox є; токен контексту збігається з токеном затвердженого шаблону; `g2_lp2a2_eq_run('EQ-H','Run',true,'Token',tok)` відхилено з `G2LP2A2:HOLD_UNAUTHORIZED`; `g2_lp2a2_eq_campaign(tok)` повернув `HOLD_UNAUTHORIZED`, `solvesCalled = 0`; `outputs/` без змін, теки результатів немає, дерево git чисте.
4. **Активація.** Створено `G2_LP2A2_EQ_GO.json` рівно за полями шаблону v2 (рішення `GO_LP2A2_EQ`, URL коментаря, схвалена голова, токен, `solveLimit` 4, чотири ID у порядку, `campaignId`, файл і SHA-256 доказів контракту). Закомічено окремо безпосередньо на `4d3701e` (лише цей файл, байти LF), запушено, виконавчий клон синхронізовано і чистий. Повторна зовнішня перевірка хешів: змінилася лише перевірка `noGoFile` (як і очікувалось), 699 захищених записів без змін.
5. **Передзапускова суха перевірка GO.** Перший сценарій запуску зупинився на власній перевірці «батько HEAD = схвалена голова», бо `git rev-parse HEAD^` повернув сам HEAD. До обгортки він не дійшов. Окремий сценарій без розв’язків викликав чисту функцію `g2_lp2a2_eq_go_validate` з реальним git: **`pass = 0`, `failed = [activationBinding]`**, усі інші десять перевірок істинні. Кампанію зупинено (§ 2).
6. **Закриття.** Повторення лише для читання `g2_lp2a2_eq_verify` — `NO_RECORDS`; архів на двох носіях; відкликання GO окремим комітом; після відкликання правильний токен із `Run=true` для всіх чотирьох ID відхилено (`HOLD_UNAUTHORIZED`), обгортка — `HOLD_UNAUTHORIZED`, `solvesCalled = 0`, записи не змінено, теки результатів немає.

## 2. Причина HOLD

Рядок 54 `matlab/g2/lp2a2/g2_lp2a2_eq_go_validate.m` визначає батьківський коміт так:

`gitOut(repo, 'rev-parse HEAD^')` → `system(sprintf('git -C "%s" %s', repo, args))`.

Під Windows MATLAB передає рядок у `cmd.exe`, де `^` — символ екранування. Кінцевий `^` зникає, git отримує `rev-parse HEAD` і повертає **сам коміт активації**, а не його батька. Перевірка `activationBinding` (батько HEAD дорівнює схваленій голові) тому завжди хибна. Виміри в тому самому клоні:

| Запит git через `system()` | Результат |
|---|---|
| `rev-parse HEAD` | `91667cfb…` (коміт активації) |
| `rev-parse HEAD^` (як у валідаторі) | `91667cfb…` — **батька не отримано** |
| `rev-parse "HEAD^"` (діагностика) | `4d3701e1…` (схвалена голова) |
| `rev-parse HEAD~1` (діагностика) | `4d3701e1…` |
| `diff --name-only 4d3701e HEAD` | `matlab/g2/lp2a2/G2_LP2A2_EQ_GO.json` (лише GO) |

Діагностичний виклик того самого чистого валідатора з батьком, знайденим через `"HEAD^"` у лапках, повертає `pass = 1` (усі 11 перевірок). Цей виклик **не використовувався** для активації: він лише показує, що вада локалізована в одному місці.

**Чому 64 контрактні тести цього не виявили.** Тест E8 підставляє git-запити (`headParent` задано функцією-заглушкою), тому реальний шлях `system()` із `^` ніколи не виконувався. Інші виклики git у `matlab/g2/lp2a2/` (`rev-parse HEAD`, `merge-base --is-ancestor`, `diff --name-only`) без `^` і працюють правильно.

**Чому обхід неможливий в межах протоколу.** Для чинного валідатора потрібно, щоб `git rev-parse HEAD` дорівнював схваленій голові (це все, що він отримує через втрачений `^`), але тоді коміт активації порожній і файл GO не міг би бути його єдиною зміною. Усунення вимагає змінити джерело `matlab/g2/lp2a2/` (отже, його відбиток, закріплення політики і токен) або підмінити git на шляху виконання; і те, й інше заборонено протоколом і підірвало б захист, який валідатор забезпечує. Тому обгортку не викликано, повтору немає.

## 3. Стан після HOLD

- **Розв’язки:** 0 з 4; теки спроб немає. Жодного запису для архівного порівняння. Таблиця C1–C11, контраст, розкриття, прогноз S9 — **не застосовні** (немає даних); рисунки порівняння не створювалися (немає записів).
- **Захищені записи:** 541 файл, дерево `20f2d54fb59395f373b7c7f7ea4437d69fbdf3be8a8710b96077881c049218ef`, і 158 файлів LP2-A1 — ідентичні до активації, після неї та після відкликання (`LP2A2_EQ_PROTECTED_*.json`).
- **Архів:** `NewMetacomp_G2_LP2A2_EQ_HoldEvidence_20261125.zip`, SHA-256 `4f60ddfd373a80655c49cdba9f8052d109140a9294b51ccedef59f8f8d5df1da`, маніфест `f2a258199ae12034c39bf36f8dbaaadff7c02e3cbc88cb70f534f09d059c1e44`. Копії: локально `Documents/NewMetacomp_LP1_archive_backup/` (внутрішній SSD) і корінь знімного USB-диска `D:` (NTFS, змінний пристрій, фізично окремий). На обох перевірено хеш файлу та хеш кожного елемента. Архів містить файл GO, журнали, сценарії та JSON передперевірок; запис про відкликання створено після архіву.
- **Відкликання:** `91718b0`; доказ відмови — `LP2A2_EQ_POST_REVOCATION.json`.
- **Обмеження доказу:** метод захищає від помилок, але не від узгодженого втручання у локальний клон; одноразовість спроби забезпечує лише локальна тека.

## 4. Що з цього випливає (для рецензії; не рішення і не авторизація)

1. **Мінімальне виправлення джерела** (потребує нового закріплення): розв’язувати батька без `^` у неекранованому вигляді, наприклад `rev-parse HEAD~1` або `rev-parse "HEAD^"`.
2. **Тест на реальному git:** контрактний тест E8 має створювати тимчасовий репозиторій із двома комітами (другий змінює лише GO) і виконувати валідатор через той самий `system()` на Windows, плюс негативний тест із неправильним батьком; зовнішня Python-перевірка повинна окремо повторювати ту саму умову.
3. **Нові закріплення:** новий відбиток LP2-A2, політика, токен, шаблон GO і докази контракту v3; нова рецензія готовності; нова окрема авторизація на нову голову. Чинна авторизація стосується голови `4d3701e` і виконана без розв’язків.
4. **Операційно:** для запуску потрібно ≥ 8,2 ГіБ вільної пам’яті перед стартом і жодного іншого процесу MATLAB (інші сесії на цьому комп’ютері його використовують); достатній запас усередині MATLAB — ≥ 7,3 ГіБ після завантаження контексту.
5. Фізичне продовження S9–S11 лишається HOLD.
